# Strategy: what to build next (2026-08-04)

Agreed position between Claude and ChatGPT/Codex, grounded in live queries.

## The situation

The platform is **data-rich and enrichment-rich**. GTI 100%, AbuseIPDB/
MaxMind/FireHOL 82.3%, LLM 95.9%; `ip_rep` on every event; novelty tracked
across all 123,795 IPs. Adding more collection or more reputation feeds has
close to zero marginal value.

## The thesis (both models agree)

**Stop adding collection/enrichment. Build synthesis that reputation feeds
structurally cannot provide.**

### The evidence that settles it

`170.101.101.98` — the single largest source in the last 24h:

| Property | Value |
|---|---|
| Events | 380,345 (largest single source) |
| Novelty | NEW — unseen in the prior 30 days |
| Site concentration | **db4lamedtech ONLY** (medtech sector) |
| Port | **80 only** |
| `ip_rep` | **NONE — unclassified** |

100% GTI coverage did not flag it, because it is unknown to reputation
sources *by definition*. It was found by comparing behaviour across sites —
something only this platform can do. Codex: "exactly the kind of signal
commercial/intel feeds miss because they flatten context."

### Sector placement is the unique asset

| Sensor | Sector | Dominant activity |
|---|---|---|
| db1lapetro | petrochemical | Heralding credential capture (443k) |
| db4lamedtech | medical tech | Suricata + Galah web (94k) |
| rmm-prod-01 | remote management | Cowrie SSH (30k) |
| pbx-prod-01 | VoIP / telephony | Cowrie + Sentrypeer SIP |
| hivev2 | — | 386k events from only **32** unique IPs |

Of the top 3,000 sources: **44% hit exactly one site**, 32% hit four or more.
Targeted and indiscriminate activity are cleanly separable — that is the
basis of a product nobody else can produce.

## Deliverables, ranked (merged view)

1. **Cross-sector differential analysis** — rank IPs/ASNs/ports/countries by
   sector skew. Fields: `sector_event_share`, `site_count`, `novelty_status`,
   `first_seen`, `rep_class`, plus flags like
   `medtech_only_high_volume_no_rep`.
2. **CTI digest to sit alongside the ops digest** — new high-volume IPs,
   single-site spikes, sector-exclusive ports, IPs newly expanding from one
   sector to several, reputation-blind top actors, deltas vs 7/30-day.
3. **Cowrie session/TTP analyzer** — reconstruct sessions: successful
   credentials → command sequences → downloaded URLs/hashes → persistence.
   Cluster by command similarity; report new TTP clusters. 1,770 commands and
   272 successful logins/day currently analysed by nothing.
4. **Reputation-blind prioritization queue** — rank entities with weak/absent
   `ip_rep` by event count, site/sector exclusivity, port specificity, login
   success, command activity, first-seen, recurrence.
5. **Unknown-but-important watchlist** — persistent tracking of statistically
   unusual entities: sector-exclusive heavy hitters, cross-sector expanders,
   quiet recurrent sources, unexplained Cowrie successes.

## Additive enrichment — very little

Worth it (behavioural feature extraction, not new feeds):
- ASN/org **normalised for grouping**, not just lookup.
- HTTP metadata already in logs: user-agent, URI path, host header, status.
- Payload URL/domain extraction from Cowrie and web logs.
- rDNS/passive DNS for high-priority unknowns only.
- JA3/JA4 only if TLS telemetry is already captured.

**Not worth it:** more IP reputation feeds. At 100%/82.3% coverage they add
noise and false confidence.

## Do NOT

- Revive the dormant connectors (broken, per operator).
- Write to MISP or OpenCTI (pull-only).
- Build another enrichment dashboard.
- Treat `ip_rep` as the primary risk score — it is blind to what matters most.
- Bury unknown actors because they lack reputation. That is the signal.
- Rank on global top-talkers without sector context.
- Have LLMs classify every raw event — cluster and summarise first.
- Start a grand ATT&CK ontology project before shipping daily findings.

## LLM server roles

- **Mac Studio 128 GB** — synthesis and narrative from precomputed stats;
  final report writing. Large context, no raw-event ingestion.
- **RTX 5080 16 GB** — fast tactical classification: label Cowrie command
  snippets, web request clusters, score unknown actors. Small structured
  prompts, JSON in / JSON out.
- **A6000 48 GB (pending)** — heavier clustering and multi-day actor
  summaries, sector differential narratives, "what changed vs baseline".

Architecture: deterministic stats → deterministic clustering → LLM explains
clusters and labels behaviour → human review. Codex's summary of the strategic
move: *"make the honeynet produce judgments, not just enriched events."*
